# Create a Linear Issue

Create a new issue using the available Linear integration. Discover its issue-creation, team lookup, and label lookup tools rather than assuming agent-specific tool names. If no Linear integration is connected, report that requirement; do not claim an issue was created.

## Required structure

The issue description must always have this structure, in this order:

### 1. Acceptance Criteria (always required)

Written from the point of view of the user, not the implementation. Plain bullet statements of what must be true.

Example:
```
## Acceptance Criteria
* Existing queries continue to return the same results.
* Invalid input produces a clear error.
* Supported Django versions retain the documented behavior.
```

### 2. Technical Specification (optional)

Only include this section if you already know implementation details — specific files, functions, data model changes, endpoints, etc. If nothing concrete is known yet, **omit the section entirely**. Do not write a placeholder or "TBD".

### 3. Plan (optional)

Only include this section if a full plan was already generated by an agent in plan mode during this conversation. Paste that plan. Do not write your own ad hoc plan here — this section is specifically for a plan mode output, not general notes.

## Labels

- If the issue describes a bug (something broken, wrong, or regressed), add the label `Category:Bug`.
- Otherwise, add no category label unless the user asks for one.

## Defaults

- Status: **Todo** (never start it in progress).
- Cycle/Sprint: **none** — leave it outside of any cycle.
- Only deviate from these two defaults if the user explicitly says to (e.g. "put it in the current sprint").

## Team

Use the team the user names, or resolve the team from an existing issue associated with the task. If neither supplies the team, ask the user; do not assume the team of another repository.

## Steps

1. Resolve the team as described above with the available team lookup tool.
2. If adding the bug label, use the available label lookup tool for that team to find the `Category:Bug` label ID (create it only if it doesn't exist and the user confirms).
3. Build the description following the structure above.
4. Call the available issue-creation tool with team, title, description, status = Todo, no cycle, and labels if applicable.
5. Report back to the user: the issue ID/URL, title, and whether the Bug label was applied. Keep it short.
